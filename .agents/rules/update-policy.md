# Incremental update policy

For an existing topic:

1. Read the complete research package, learning page, and coverage map.
2. Compare source headings, versions, conclusions, examples, and limitations with the published presentation.
3. Preserve stable topic IDs, routes, personal experience, source-inspected findings, and valuable hand-authored explanations.
4. Change only affected sections and reusable components.
5. Add or update relationships only when both the technical relationship and destination route exist.
6. Update coverage rows and visible version/update metadata.
7. Run deterministic validation, the Astro build, and the semantic/visual review.

Never recreate the knowledge base for a localized change, duplicate a route, or make the presentation layer an independent source of technical truth.
