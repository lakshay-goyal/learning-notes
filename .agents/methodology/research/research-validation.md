# Research validation

Use after drafting and before setting a topic to `validated`. Read `.agents/policies/validation-policy.md` in full.

1. Run topic validation and fix structural failures.
2. Create an objective-to-section/source matrix in the research plan; mark unanswered questions explicitly.
3. Re-open primary evidence for consequential, version-sensitive, or surprising claims.
4. Compare every API/configuration example to the recorded version.
5. Verify every cited repository path at the pinned revision and downgrade anything not actually inspected.
6. Re-run safe executable examples or label them `NOT EXECUTED`; record command, date, and result for tested examples.
7. Review teaching sequence, terminology, diagrams, alternatives, and applicable production trade-offs.
8. Run strict topic validation, update the central index, then run strict validation across the knowledge base.

Completion condition: all gates pass and remaining limitations are visible. If evidence is incomplete, retain a non-validated status. Never convert an inference into a sourced fact to satisfy a template.
