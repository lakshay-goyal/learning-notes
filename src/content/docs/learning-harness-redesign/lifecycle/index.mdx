## The missing distinction

A learner may want to:

1. understand a concept now
2. save a source-backed note
3. publish a visual lesson
4. practise an implementation
5. be questioned on the topic
6. maintain the topic when versions change

Those are six workflows with six different write permissions and six different
success measures. Collapsing them is why a normal explanation produced a research
package.

The order is not arbitrary. Stage 5 before stage 6 because prose written before
the knowledge model is prose that has to be rewritten. Stage 8 interleaves with
stages 6 and 7 rather than following them, because retrieval only works when it
interrupts.

## Progressive disclosure

| Level | Learner job | Best representation |
| --- | --- | --- |
| Quick recall | decide whether to invest | short definition and use condition |
| Visual understanding | build a mental model | mechanism, flow, diagram, worked example |
| Complete understanding | go deep | module, deep dive, original research |
| Active recall | prove retrieval | interleaved checks and a review page |

A topic index should not contain every deep dive inline. Link and disclose.

## Interleaving practice

Placing all recall checks at the end makes a page a final exam. Predicting
*immediately after* the mechanism is what forces reconstruction:

```text
Teach protocol discovery
  → learner predicts what happens when the tool is missing
  → reveal the behaviour
  → continue to schema validation
  → learner predicts which surface reports invalid input
```

Recognition is what a deferred quiz measures. Reconstruction is what interleaving
measures, and reconstruction is closer to using the thing.

<Aside type="tip" title="Keep one consolidated review">
  Interleave during the topic and keep one consolidated review page for the
  delayed pass. Both: retrieval while fresh, retrieval after a delay.
</Aside>

## The learning evidence ladder

| Evidence | Proves | Does not prove |
| --- | --- | --- |
| Read the page | exposure | understanding |
| Answer a recall question | retrieval of a claim | transfer |
| Pass a prediction question | mechanism reasoning | implementation skill |
| Run a lab | applied capability in one context | broad mastery |
| Design a novel solution | transfer and judgement | long-term retention |
| Recall after a delay | retention | automatic real-world performance |

The dashboard should show these distinctions rather than treating all activity as
"learned". That is why the revision panel reports answered prompts and not a
mastery state.

## Anti-overload rules

- Mental model before source detail.
- Short default scan path.
- A visual only where it answers a question.
- Split by learning job, not length.
- One next step per page.
- Research evidence reachable without sitting in the default path.
- Never repeat one definition across overview, module, and review.
