## The problem

The repository had good instincts and a broken shape.

```text
Methodology      → what an agent should ideally do
CLI contracts    → what the agent is allowed to produce
Astro app        → what the learner is eventually shown
```

Those three were designed separately and never reconciled. The gap was not
content quality. The content was thoughtful and source-aware. The gap was that one
topic's accidental shape had been encoded as the platform.

## Three root causes

**Research organised by artifact type.** Every topic produced the same flat
siblings — lesson, plan, sources, implementation, exercises, revision. Convenient
for a validator, but not a learner journey: understanding one mechanism meant
moving across six document types.

**Visual cardinality hardcoded.** The validator required exactly one learning page
per research slug. A methodology describing four access levels and a page hierarchy
met a machine rule that permitted none of it. Route-level disclosure existed in the
design; section-level disclosure existed in the implementation.

**Coverage counted reachability, not teaching.** A coverage map asked whether a
research heading had a destination anchor. That proves a finding can be found. It
says nothing about whether an objective is taught, assessed, or retained.

## The rebuilt contracts

| Before | Now |
| --- | --- |
| One page per research slug | One overview plus focused child pages |
| `learning.id` was both topic and page | Separate `topicId` and `pageId` |
| Heading-to-anchor coverage | Objective, concept, page, assessment coverage |
| Flat package per mode | Mode-specific profile plus a learning design |
| Config keys with no consumer | Every config key read by code, checked by `doctor` |
| Self-reported validation | Ordered gates plus machine-written receipts |
