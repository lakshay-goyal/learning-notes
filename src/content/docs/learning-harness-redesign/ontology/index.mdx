## The problem with one folder tree

A folder tree is useful for human navigation and a poor universal database:

- `AI Engineering` behaves like a domain.
- `System Design` behaves like a field or a skill.
- `DevOps` can be a field or a practice.
- `Tools` is a container, not a knowledge domain.
- `Git`, `Linux`, and `Docker` are tools or topics.

Placing every entity in one tree creates duplicate pages and arbitrary decisions.

## The canonical entities

| Entity | Is | Stable ID | Hierarchical? |
| --- | --- | --- | --- |
| **Domain** | a broad area of practice, such as AI engineering | yes | top of navigation |
| **Field** | a specialty inside a domain | yes | under a domain |
| **Skill** | something a learner can do | yes | many-to-many with topics |
| **Tool** | software a topic teaches | yes | many-to-many with topics |
| **Topic** | a bounded learning contract | yes | under a field |
| **Module** | one chapter of research | inherits topic | under a topic |
| **Page** | one focused delivery unit | yes | under a topic, by learning job |
| **Concept** | an idea the learner operates on | yes | under any number of topics |
| **Lab** | an executable artifact producing evidence | yes | attached to objectives |
| **Assessment** | an activity evidencing an objective | yes | attached to objectives |

<Aside type="caution" title="Module means two things">
  A **research module** is a chapter under `docs/<slug>/modules/`. A **module
  page** is a published page whose `learning.kind` is `module`. They are never the
  same thing, and the harness vocabulary now says so in
  <a href="/research/learning-harness-redesign/">.agents/GLOSSARY.md</a>.
</Aside>

## Which relationships are hierarchical

Use a hierarchy where a reader genuinely navigates one path:

```text
domain → field → topic → page
```

Use many-to-many where meaning does not fit a tree:

```text
skill    ↔ topic
tool     ↔ topic
concept  ↔ topic
path     ↔ topic
```

A topic about PostgreSQL index selection belongs to one field but uses two tools,
teaches three skills, and reuses concepts from database fundamentals. A tree
forces it to pick one parent and lose the rest.

## Why stable IDs matter

A route is a location. An ID is a name.

```text
Route:  /ai-engineering/model-context-protocol/       may change
ID:     ai-engineering                                does not
```

Relationships must reference IDs, not routes or labels. Renaming a label or moving
a route then updates navigation without touching a single relationship, and a
broken destination is detectable instead of silently wrong.

The harness enforces this: every taxonomy ID must exist in
`.agents/registry/taxonomy.json`, and the visual validator rejects an unknown one.

## Path design

A learning path is an ordered list of topics, not a folder. The same topic belongs
to several paths, and a path can be generated per goal rather than stored once:

```text
"ship a production API"
  → HTTP semantics → authentication → database migrations → observability

"understand vector search"
  → embeddings → indexing → retrieval → evaluation
```

Both paths reuse topics. Neither is a directory.
