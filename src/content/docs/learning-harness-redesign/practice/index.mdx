## Lab 1 — scaffold and inspect

Produce evidence that a topic plans itself into multiple pages.

<Steps>
  1. Scaffold a topic in an isolated root:
     ```bash
     mkdir -p /tmp/lab/.agents /tmp/lab/docs
     cp .agents/config.json /tmp/lab/.agents/
     cp -r .agents/templates /tmp/lab/.agents/
     printf '# K\n\n<!-- DEEP_LEARN_INDEX_START -->\n<!-- DEEP_LEARN_INDEX_END -->\n' \
       > /tmp/lab/docs/README.md

     node .agents/bin/deep-learn.mjs new "Vector Embeddings" --mode deep --root /tmp/lab
     ```
  2. Read the generated learning design:
     ```bash
     cat /tmp/lab/docs/vector-embeddings/learning.md
     ```
  3. Record the evidence: how many objectives, how many concepts, how many planned
     pages, and whether every `pageId` is unique.
  4. Prove the bound holds. Set `pagePlanning.maximumPageCount` to 3 in the copied
     config, scaffold again, and confirm the plan is clamped to 3.
  5. Prove the design is required. Delete `learning.md` and run:
     ```bash
     node .agents/bin/deep-learn.mjs validate vector-embeddings --root /tmp/lab
     ```
     Expect a failure naming the missing learning design.
</Steps>

<Aside type="tip" title="What to record">
  The command output and your observation of it. "It produced 6 pages" is a claim;
  the pasted table is the evidence.
</Aside>

## Lab 2 — find the accidental architecture

<Steps>
  1. Pick a constraint in the harness that surprised you.
  2. Answer the five questions:
     - Which file or schema forces this shape?
     - Which validator rejects the alternative?
     - Which component assumes it at runtime?
     - Which documentation claims an enforcement the code lacks?
     - Can a small fixture prove the alternative?
  3. Write the fixture and run it.
  4. Decide: is this a deliberate decision that should be enforced harder, or an
     accident that should be removed?
</Steps>

A worked example: `.agents/config.json` carried 22 keys no code read, and
`doctor` reported zero warnings because the check scanned an archived config
snapshot that repeated every key name. The answer to question 4 was "the
documentation claims enforcement the code does not provide".

## Lab 3 — migrate without losing content

<Steps>
  1. Run `node .agents/bin/deep-learn-visual.mjs inspect <slug>` and record the
     current page count and objective coverage.
  2. Write the page plan. For every planned page, name the question it answers.
  3. Create the overview. It keeps quick recall, the mental model, three
     takeaways, use conditions, and one next step.
  4. Move prose into child pages **by cut, not rewrite.** Sentences stay intact.
  5. Update `learning.md` first if the plan changed, then the pages.
  6. Rebuild the coverage map: one row per research level-two heading, `MAPPED`
     with a real anchor or `INTENTIONALLY_EXCLUDED` with a stated reason.
  7. Run the gate in order and stop at the first failing layer:
     ```bash
     node .agents/bin/harness.mjs check --layer=static
     node .agents/bin/harness.mjs check --layer=runtime
     node .agents/bin/harness.mjs receipt <slug>
     ```
</Steps>

## Lab 4 — design the failure table

Pick a system you know well. For each failure below, name the gate that must
catch it and the exact error message it should produce.

| Failure | Your gate | Your error message |
| --- | --- | --- |
| Two pages share a `pageId` | | |
| A page points to missing research | | |
| An objective has no assessment | | |
| A cited source was never opened | | |
| A learner has local storage disabled | | |
| A feature is marked done with no evidence | | |

An error message should carry the repair, not just the failure:

```text
Test failed.
```

```text
node .agents/bin/harness.mjs check: FAIL static.
  fail node .agents/bin/deep-learn-visual.mjs validate --all --strict
       Error: src/content/docs/x/index.mdx: declares no learning.assessmentIds;
              page "x-module" must say how it is assessed.
SKIPPED (an earlier layer failed): runtime, system
```

  answer="The plan is derived from page kinds, and two pages shared a kind. The generator suffixes duplicates with an ordinal (`topic-module-2`), and the validator independently rejects any duplicate `pageId`. Before the fix, the scaffold produced two pages that could never pass validation."
